# How this site actually reaches production

**Do not build this repo and deploy the output. It would take the site offline
for purchases.**

## The short version

`semiconlabs.com` runs a build produced by the client's team, hosted on cPanel.
It is not built from this repository. Changes reach it by patching that build,
not by `npm run build`.

## Why

This repo is the UI and marketing source. The client's team took an earlier
build of it, added the backend integration, and has shipped from their own copy
since. That integration was never merged back here, so this source is missing
the parts that make the site transact:

| | this repo | what is deployed |
|---|---|---|
| Purchase / OTP flow | **stub** — writes to `sessionStorage`, shows "we'll contact you" (`PreBookDialog.tsx`) | real: `marketing-leads/send-otp`, `verify-otp`, `individual-register` |
| API base URL | `VITE_API_URL` baked in at build time; **empty** in `.env` | `window.__APP_CONFIG__` read at runtime from `config.js` |
| Extra runtime files | none | `config.js`, `resume-handoff.js`, `resend-countdown.js`, `hash-scroll.js`, `analytics.js` |
| Routes | 29 (includes `/modules`, skill pages) | 17 |

A build from this source has no `config.js`, so no API, no payments, no OTP.

## So what is this repo for

It is the readable record: copy, layout, SEO metadata, and why each change was
made. Author changes here first — it is also what makes patching the compiled
bundle safe, because it tells you the exact string to search for.

## Shipping a change

1. Make the change here, typecheck, lint, commit.
2. Apply the same change to the deployed build (patch the minified chunk).
3. Verify in a browser against the patched build.
4. Repackage and hand the zip over for cPanel.

Zips must store Unix permissions `0644` for files and `0755` for directories.
A zip written without them extracts as `0600`, Apache cannot read `.htaccess`,
and the whole site returns 403.

## The real fix

Get the client team's frontend repository and merge their backend integration
into this one. Then there is a single source, this repo builds something
deployable, and steps 2–4 above disappear.

## Things live in production that are not generated by this repo

- Google Tag Manager `GTM-W75LQ95X` — mirrored into `index.html` so the repo
  reflects production, but the deployed copy was added by hand to the build.
- `launchingindex.html` and `Banner.png` — present on the server since Aug 2026,
  origin unconfirmed, nothing here references them. Do not delete without asking.
